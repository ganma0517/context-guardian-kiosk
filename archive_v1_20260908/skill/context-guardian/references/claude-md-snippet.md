# CLAUDE.md 片段（貼到專案根目錄的 CLAUDE.md）

把這段加進專案的 `CLAUDE.md`（每個 session 都會自動載入，不像 skill 要等觸發判斷）：

```markdown
## 上下文管理（一律檢查，不用等我提起）

任何工具呼叫預期回傳大量內容、任務會跨多個 turn、或一個階段做完準備換下一階段時，
先查閱並套用 context-guardian skill 的規則，不要等我提到「context」「token」「太長」
這類字眼才反應。特別是：

- 大型工具輸出先寫檔案，對話中只留路徑 + 摘要
- 審稿原文、變數操作型定義、模型設定這類需要逐字保留的內容，絕不自動摘要
- 一個階段做完，先把結論寫回設定檔，再提醒我可以開新對話
```

## 為什麼需要這段，而不是只放 SKILL.md

Skill 的 metadata（name + description）雖然一直在 Claude 的 available skills 清單裡，
但要不要讀取 SKILL.md 本體，仍然是 Claude 每次自行判斷的結果。對於單步、看起來簡單
的操作（例如「讀這份逐字稿」），即使規則明明適用，Claude 也可能覺得不需要動用 skill 而
跳過。CLAUDE.md 是每個 session 開頭就強制載入的內容，把「要不要檢查」這個判斷題，
換成「一律檢查」的直接指令，兩者搭配才會接近真正的被動：不用使用者記得喊它，
它自己會在背景把關。
